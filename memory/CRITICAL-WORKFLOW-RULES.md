# 关键工作流程规则 - 必须严格遵守

## 事故教训记录

### 2025-03-19 严重事故 - 覆盖用户未提交的代码

#### 事故经过
1. **第一次提交 (a315c5e)**：基础版本，没有饼图、统计、分享功能
2. **用户本地开发**：添加了 PieChart、GachaDetail、分享等功能，**但未提交到 git**
3. **我基于 git 修改**：只看到了第一次 commit 的代码，没有看到用户本地未提交的修改
4. **我提交修改**：覆盖了用户本地未提交的代码

#### 后果
- 用户丢失已完成的饼图、统计、分享功能代码
- 代码**无法恢复**（从未提交到 git，不在任何分支、stash 或备份中）

#### 根本原因
- **没有执行 `git status`** 检查未提交的修改
- **基于 git HEAD 而不是本地文件**进行修改
- **直接覆盖**用户文件而不确认内容

## 修改代码前的强制检查清单

### 必须执行（按顺序）：

1. **检查 git 状态（最重要！）**
   ```bash
   git status
   ```
   - 如果有未提交的修改（红色或绿色文件），**立即停止！**
   - 告知用户："我发现您有未提交的修改，请先提交您的工作"
   - 等待用户提交后再继续

2. **确认当前工作目录**
   ```bash
   git diff --name-only
   ```
   - 了解哪些文件被修改了
   - 确认修改的内容和范围

3. **基于本地文件修改（关键！）**
   - 使用 `Read` 工具读取**当前本地文件**内容
   - 使用 `Edit` 工具基于当前内容修改
   - **绝不**直接覆盖文件或基于 git 历史重建文件
   - **绝不**假设本地文件与 git HEAD 一致

4. **修改后立即验证**
   - 确认修改是否正确应用
   - 检查是否意外删除了其他代码
   - 确认用户之前的功能仍然保留

5. **提醒用户提交**
   ```bash
   git add <修改的文件>
   git commit -m "描述修改内容"
   ```

## 危险操作警示

### 绝对禁止的操作：

1. ❌ **不检查 `git status` 就直接修改文件**
   - 这是最危险的操作，会导致覆盖未提交的代码
   - 必须养成习惯：任何修改前先执行 `git status`

2. ❌ **基于 git HEAD 而不是本地文件进行修改**
   - 用户可能有未提交的修改，HEAD 不代表实际文件状态
   - 必须使用 `Read` 工具读取当前文件

3. ❌ **直接覆盖用户文件而不确认内容**
   - 绝不使用 `Write` 工具覆盖现有文件（除非明确允许）
   - 优先使用 `Edit` 进行增量修改

4. ❌ **忽略用户提到的"之前做好的"功能**
   - 如果用户说"我之前做好的..."，立即停止操作
   - 询问代码位置，确认是否存在未提交的修改

### 必须警惕的信号：

- 🚨 用户说"我之前做好的..." → 立即停止，询问代码在哪里
- 🚨 用户说"我的代码不见了" → 检查是否被覆盖
- 🚨 `git status` 显示有未提交的修改 → 绝对不能直接修改
- 🚨 用户说"我没有提交" → 立即检查本地文件状态

## 正确的工作流程示例

### 场景：用户要求修改功能

**错误的做法（导致事故）：**
```
用户：帮我修改数据处理逻辑
我：（直接开始修改，没有检查 git status）
（基于 git HEAD 修改，覆盖了用户本地未提交的代码）
结果：用户丢失代码
```

**正确的做法：**
```
用户：帮我修改数据处理逻辑

我：
1. 执行 git status
   （发现未提交的修改：PieChart.vue, GachaDetail.vue 等）

2. 立即停止修改！
   告知用户："我发现您有未提交的修改（PieChart.vue, GachaDetail.vue），
   这些是您之前做的功能吗？请先提交您的工作，我再进行修改。"

3. 用户提交后：
   git add . && git commit -m "添加饼图和统计功能"

4. 现在可以安全地修改了
   基于本地文件读取和修改
```

## 记忆优先级

**最高优先级（必须遵守）：**
1. ✅ 修改前执行 `git status`
2. ✅ 不覆盖未提交的修改
3. ✅ 基于本地文件修改，不是 git HEAD

**高优先级：**
1. ✅ 修改后提醒用户提交
2. ✅ 验证修改正确性
3. ✅ 保留用户现有功能
